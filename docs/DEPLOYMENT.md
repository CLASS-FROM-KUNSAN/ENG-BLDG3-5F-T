# 강의실 PC 배포 전 확인

한 번만 하면 되는 것들입니다. **빠뜨리면 수업이 끝난 뒤에야 압니다.**
여기 적힌 것은 전부 실제로 당한 것들입니다.

---

## 1. 마이크 — 가장 흔한 사고

기본 마이크를 믿지 마세요. 2026-11-13 실기 PC 의 기본 마이크는
`마이크 배열 (Audio Share)` 라는 **가상 장치**였고, 61초 녹음에
0 아닌 바이트가 **하나도** 없었습니다.

```bat
.venv\Scripts\python -m gymhall devices
```

목록에서 실제 장치를 찾아 `config.toml` 에 이름 일부를 적습니다.

```toml
[recording.audio]
mic_device = "인텔"          # 또는 "Focusrite" 등 실제 장치
system_device = ""           # 비우면 기본 스피커의 루프백 (보통 맞습니다)
```

### 확인

1분만 녹화해 보고 레벨을 봅니다.

```bat
.venv\Scripts\python -m gymhall record start -l 마이크테스트 -m 1 --no-upload
```

> `--dry-run` 은 **녹화를 합니다.** 업로드만 흉내 냅니다. 녹화 자체를
> 막으려면 `--no-upload` 입니다.

끝나면 로그에 이런 줄이 있어야 합니다.

```
[mic] 녹음 시작: 인텔® 스마트 사운드 ... -> 20261113_...mic.wav
[mic] 녹음 종료: 60.0초, 최대레벨 0.182
```

최대레벨이 `0.000` 이고 아래 오류가 뜨면 장치가 틀린 것입니다.

```
[mic] 레벨이 정확히 0 입니다. 조용한 것이 아니라 신호가 아예
      안 들어왔습니다 — 진짜 마이크라면 조용한 방에서도 미세한
      잡음은 잡힙니다.
```

**"정확히 0" 과 "작은 값" 은 다릅니다.** 진짜 마이크는 조용한 방에서도
ADC 열잡음으로 ±1 LSB 는 흔들립니다. 정확히 0 이면 가상 장치이거나,
음소거이거나, 권한이 없는 것입니다.

### 자동 선택을 켜 둔 경우

`mic_device` 를 비워 두면 녹화 시작 전에 마이크를 1.5초씩 시험해
살아 있는 것을 고릅니다. **고른 결과를 로그에서 확인하세요.**

```
기본 마이크 '마이크 배열 (Audio Share)' 는 신호가 정확히 0 이라
'인텔® 스마트 사운드' 로 바꿉니다(최대레벨 0.00089).
```

이 줄이 떴다면 자동 선택이 작동한 것이고, `mic_device` 에 그 이름
일부를 적어 두면 다음부터 시험 없이 바로 씁니다. 자동 선택은
**안전망이지 설정을 대신하는 것이 아닙니다.**

### 그래도 0 이면

Windows 설정 > 개인 정보 및 보안 > **마이크** > "데스크톱 앱이 마이크에
액세스하도록 허용" 이 켜져 있는지 봅니다. 꺼져 있으면 Windows 가
오류 없이 무음을 흘려보냅니다.

## 2. 화면 — 모니터가 둘이면

빔프로젝터가 따로 있으면 `-i desktop` 은 **두 화면을 이어 붙인** 그림을
잡습니다. 판서 쪽이 절반으로 줄고, 교탁 화면의 메일까지 같이 올라갑니다.

```bat
.venv\Scripts\python -m gymhall devices
```

화면 목록에서 번호를 확인하고 적습니다.

```toml
[recording.video]
monitor = 2        # 0 = 전체 바탕화면
```

창 하나만 찍으면 더 좁고 안전합니다. 그쪽이 우선입니다.

```toml
window_title = "PowerPoint 슬라이드 쇼"   # 있으면 monitor 는 무시됩니다
```

> **`backend = "ddagrab"` 을 쓰고 화면이 둘 이상이면 주의하세요.**
> ddagrab 의 화면 번호는 그래픽 드라이버가 정한 순서라, 여기 적은
> 번호와 다를 수 있습니다. 엉뚱한 화면이 찍히면 기본값인
> `gdigrab` 으로 바꾸세요 — 좌표로 잘라내므로 정확합니다.
> 실행하면 로그에 경고가 뜹니다.

## 3. 파이썬 — `python` 이 안 되면 `py`

```bat
python --version
```

아무것도 안 나오면 `python` 이 `C:\Windows\system32\python`(Microsoft
Store 스텁)으로 잡힌 것입니다. 오류도 없이 조용히 끝납니다.
`py --version` 을 쓰세요. venv 를 만든 뒤로는 `.venv\Scripts\python` 을
쓰므로 이 문제가 없습니다.

## 4. 과목과 레포

같은 과목이 두 강의실 PC 에 배포될 수 있습니다. 기기 이름이 에셋
이름에 들어가야 서로 덮어쓰지 않습니다.

```toml
machine_label = "공학관-401호"     # PC 마다 다르게
```

과목을 적어 두지 않으면 **업로드를 아예 하지 않습니다**(어느 레포로
갈지 모르므로). 경고만 찍고 로컬에는 남깁니다.

```toml
[[eclass.course_repos]]
id    = "2026211605005"
name  = "기초웹프로그래밍"
owner = "CLASS-FROM-KUNSAN"
repo  = "web-programming-2026-2"
```

## 5. 홈 백업과 정리

강의실 PC 의 홈 폴더(`%USERPROFILE%`)를 매일 GitHub 릴리스(`home-YYYY-MM-DD`)에
올리고, **올라간 것이 확인된 파일만** 로컬에서 지울 수 있습니다. 둘 다
**기본으로 꺼져 있습니다.** `config.toml` 에서 켜야 일합니다
(키 설명은 [CONFIG.md](CONFIG.md)).

```toml
[backup.home]
enabled = true            # 매일 백업 (HomeBackup 작업, 기본 03:13)

[backup.home.prune]
enabled = true            # 확인된 파일 정리 (HomePrune 작업, 기본 05:43)
min_age_hours = 24        # 올라간 지 이만큼 지난 것만 지웁니다
```

작업은 [register_tasks.ps1](../scripts/register_tasks.ps1) 이 등록합니다
(`-HomeBackupTime`, `-HomePruneTime` 으로 시각 변경, `-SkipHome` 으로 빼기).

**올리지 않는 것**
- 홈 바로 아래의 `AppData` 와 `.` 으로 시작하는 폴더 (더 아래의 `.git` 등은 올립니다)
- 정션/심볼릭 링크 (따라가지 않습니다)
- OneDrive 의 클라우드 전용 파일 (읽으면 내려받기가 일어납니다)
- 비밀 파일: `ntuser.*`, `.env`, `*.pem`, `*.key`, `id_rsa*`, `*.kdbx`, `config.toml` 등
  (`backup.home.exclude_names` 로 바꿉니다)

**지우는 조건 — 하나라도 어긋나면 남깁니다**
- 업로드마다 매니페스트를 올리고, 매니페스트는 앞 매니페스트의 해시를 품어
  사슬이 됩니다. 정리는 로컬 기록이 아니라 **GitHub 에서 내려받은 사슬**을
  처음까지 확인합니다. 한 고리라도 해시가 틀리거나 빠지면 **한 개도 지우지 않습니다.**
- 매니페스트에 적힌 홈 폴더가 지금 홈과 같아야 합니다(다른 홈의 사슬이면 하나도 안 지움).
- 그 파일이 든 묶음(zip)이 릴리스에 있고, **GitHub 가 알려 주는 SHA-256 digest 가
  매니페스트와 같아야** 합니다. digest 가 없으면 크기가 맞아도 지우지 않습니다.
  2GiB 를 넘어 나뉜 묶음은 `*.parts.json` 을 내려받아 원본 SHA-256·조각 수를
  대조하고, 조각마다 digest 가 있어야 합니다. 확인이 안 된 파일은 대기로 남고
  `backup prune` 은 1 로 끝납니다.
- 지금 파일의 SHA-256 이 올라간 것과 같아야 합니다(그사이 고쳤으면 남깁니다).
- 실제로 열리는 파일 이름이 매니페스트의 경로와 같아야 합니다. `a.` · `a ` ·
  `LONGDI~1` 같은 Windows 별칭은 다른 파일을 가리키므로 지우지 않습니다.
- 홈 밖, 정션 너머, gymhall 설치 폴더·데이터 폴더·설정 파일은 지우지 않습니다.
- 파일만 지웁니다. **폴더는 그대로 둡니다.**

**알아 둘 것**
- 처음 백업은 홈 전체(수십 GB, 예: 약 65 GB)라 작업의 12시간 제한을 넘을 수
  있습니다. 괜찮습니다 — 다 올라간 묶음과 고리는 남고, 다음 날부터 나머지를
  이어서 올립니다. 며칠에 걸쳐 끝납니다.
- 백업과 정리는 **동시에 돌지 않습니다**(잠금). 정리할 시각에 백업이 아직
  돌고 있으면 정리는 그날을 건너뜁니다.
- 설치마다 무작위 ID 가 생겨 사슬 이름에 들어갑니다. 이 ID 는 **첫 실행 때**
  상태 파일(`state\home_backup.sqlite`)에 만들어집니다. 그래서 설정 파일만
  복사한 PC 끼리는 ID 가 다르지만, **첫 백업 뒤에 디스크 이미지를 떠서
  복제하면 모든 복제본이 같은 ID** 를 가집니다. 이미지를 뜨기 전에 상태
  파일을 지우세요(`state\home_backup.sqlite`, 같은 이름의 `-wal`/`-shm`
  파일까지). 같은 ID 여도 실행마다 다른 번호가 이름에 들어가고, 같은 이름의
  에셋은 덮어쓰지 않으므로 서로의 백업을 지우지는 않습니다. 다만 두 PC 의
  사슬이 같은 PC 것처럼 섞여 보입니다.

올린 것은 로그 폴더(`%LOCALAPPDATA%\gym-w-hall-2f\logs`)의 `home-chain.log` 에
디렉터리별로, 지운 것은 `home-prune.log` 에 지운 순서대로 한 줄에 하나씩
남습니다.
처음 켤 때는 `backup prune --dry-run` 으로 지울 목록을 먼저 보세요.

## 6. 마지막 — 종료 코드

무인 작업(작업 스케줄러)으로 돌리면 **화면을 보는 사람이 없습니다.**
그래서 실패는 반드시 종료 코드로 나와야 합니다.

| 명령 | 0 이 아닌 경우 |
|---|---|
| `eclass sync` | 업로드한 파일이 하나도 없는데 올릴 것이 있었을 때 |
| `upload <경로>` | 같음 / 과목을 몰라 건너뛰었을 때 |
| `transcribe queue` | 전사 실패가 있거나, 결과를 못 올렸을 때 |
| `record start` | 다른 녹화가 돌고 있어 한 프레임도 못 찍었을 때 |
| `backup home` | 묶음 업로드가 실패했거나, 올릴 것이 있었는데 매니페스트를 못 올렸을 때 |
| `backup prune` | 사슬 확인에 실패했거나(아무것도 지우지 않음), GitHub 에서 묶음을 확인하지 못한 파일이 있거나, 지우는 중 오류가 있었을 때 |

작업 스케줄러의 "마지막 실행 결과" 가 `0x0` 이 아니면 로그를 보세요.
로그는 `%LOCALAPPDATA%\gym-w-hall-2f\logs` 에 있습니다.
