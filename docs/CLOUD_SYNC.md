# PC 없이 자료 수집하기 (GitHub Actions)

작업 스케줄러 방식에는 피할 수 없는 구멍이 있습니다.

> **노트북이 꺼져 있거나 절전이면 그 시각의 수집을 놓칩니다.**
> `StartWhenAvailable` 덕에 다음에 켤 때 밀려서 실행되긴 하지만,
> 며칠 안 켜면 그만큼 늦습니다. 들고 다니는 노트북에서는 자주 일어납니다.

`.github/workflows/eclass-sync.yml` 은 이걸 GitHub 서버에서 돌려 해결합니다.
**PC 가 꺼져 있어도 하루 세 번 수집해 릴리스에 올립니다.**

녹화는 화면과 오디오 장치가 필요하므로 이 방식으로 할 수 없습니다.
**자료 수집(1번 기능)만** 해당됩니다.

---

## 먼저 알아야 할 것 — 그냥 좋기만 한 선택이 아닙니다

### 1. 학교 계정 비밀번호를 GitHub 에 맡기게 됩니다

GitHub Secrets 는 암호화돼 저장되고 로그에도 가려져 나옵니다.
저장소 관리자도 값을 다시 볼 수 없습니다. 하지만:

- **워크플로 파일을 수정할 수 있는 사람은 실행 중에 값을 꺼내 쓸 수 있습니다.**
  (`run: echo $GYMHALL_ECLASS_PASSWORD | base64` 같은 식으로)
- 따라서 **협업자가 있는 저장소에서는 쓰지 마세요.**
- **public 저장소에서는 절대 쓰지 마세요.** Fork PR 에는 시크릿이
  전달되지 않지만, 설정 실수 한 번이면 노출됩니다.

혼자 쓰는 private 저장소라면 받아들일 만합니다.
그게 아니면 로컬 작업 스케줄러 방식을 쓰세요.

### 2. 학교 서버가 보기에 낯선 IP 입니다

GitHub 러너는 미국 등지의 데이터센터에 있습니다.
학교가 해외 IP 를 막아 두었다면 로그인 단계에서 실패합니다.
돌려 보기 전에는 알 수 없습니다. 실패하면 로그에 그대로 나옵니다.

### 3. 비밀번호가 바뀌면 조용히 실패합니다

학교는 주기적으로 비밀번호 변경을 요구합니다. 바꾼 뒤 Secrets 를
갱신하지 않으면 매번 로그인에 실패합니다. 그 상태로 반복되면
**계정이 잠길 수 있습니다.**

이 도구는 로그인 실패 시 **재시도하지 않습니다.** 그래도 하루 세 번
시도하므로, 실패 알림을 받도록 설정해 두는 편이 안전합니다
(저장소 Settings → Notifications, 또는 Actions 실패 메일).

## 설정

### 1. 저장소가 private 인지 확인

Settings → General → 맨 아래 Danger Zone 에서 확인합니다.
public 이면 **여기서 멈추세요.**

### 2. Secrets 두 개 등록

저장소 → **Settings** → **Secrets and variables** → **Actions**
→ **New repository secret**

| 이름 | 값 |
|---|---|
| `ECLASS_ID` | 학번 |
| `ECLASS_PASSWORD` | eClass 비밀번호 |

> 이름을 정확히 이 대로 적어야 합니다. 대소문자도 같아야 합니다.

### 3. 손으로 한 번 돌려 보기

저장소 → **Actions** 탭 → 왼쪽에서 **eClass 자료 수집** →
**Run workflow** → `dry_run` 을 `true` 로 두고 실행.

`true` 면 수집만 하고 릴리스에 올리지 않습니다. 로그인과 수집이
되는지만 먼저 확인하는 용도입니다.

성공하면 다시 `false` 로 한 번 더 돌려 릴리스까지 확인하세요.

### 4. 자동 실행 확인

성공했다면 그 뒤로는 알아서 돕니다. 기본 일정은 한국 시간으로
**07:23 / 13:23 / 19:23** 입니다.

바꾸려면 `.github/workflows/eclass-sync.yml` 의 `cron` 을 고치세요.
**UTC 기준**이라 한국 시간에서 9시간을 빼야 합니다.

```yaml
- cron: '23 22 * * *'   # UTC 22:23 = KST 07:23 (다음 날)
```

> 정각(`0 * * * *`)은 피하세요. 전 세계 작업이 몰려 몇십 분씩 밀립니다.

## 로컬 방식과 같이 써도 되나요

됩니다. 중복 수집은 일어나지 않습니다.

이 도구는 **파일 내용 해시**로 중복을 판단합니다. Actions 가 먼저 올린
파일을 PC 가 다시 받더라도, 해시가 같으면 업로드하지 않습니다.
반대도 마찬가지입니다.

다만 **로컬 폴더와 Actions 의 상태 파일은 서로 모릅니다.** PC 쪽은
Actions 가 이미 받은 자료를 "처음 보는 것" 으로 여겨 한 번 더
**다운로드**합니다(업로드는 안 합니다). 디스크만 조금 더 쓰는 수준입니다.

둘 중 하나만 쓰고 싶다면:

- **Actions 만**: 작업 스케줄러에서 `EclassSync` 작업을 지우세요.
  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\register_tasks.ps1 -Remove
  ```
  그 뒤 녹화 관련 작업만 다시 등록하면 됩니다(`-SkipSchedule` 등 참고).

- **로컬만**: `.github/workflows/eclass-sync.yml` 을 지우세요.

## 동작 방식

```
GitHub 서버 (하루 3회)
  │
  ├─ 저장소 체크아웃
  ├─ Python + Playwright + Chromium 설치
  ├─ config.example.toml 로 config.toml 생성
  │    (학번은 Secrets 에서, 녹화·전사는 끔)
  ├─ 이전 상태 파일 복원 (actions/cache)
  │    없으면 전부 '새 자료' 로 보고 다시 받습니다
  ├─ python -m gymhall eclass sync
  │    로그인 → 과목 순회 → 새 자료만 저장 → 릴리스 업로드
  └─ 실패하면 로그를 Artifact 로 남김 (7일 보관)
```

러너는 매번 새 머신이라 아무것도 남지 않습니다. 그래서:

- **상태 파일은 `actions/cache` 로 이어 붙입니다.** 캐시가 비워져도
  (GitHub 는 7일 미사용 캐시를 지웁니다) 내용 해시 덕분에 **중복
  업로드는 일어나지 않습니다.** 다시 받기만 할 뿐입니다.
- **수집한 자료 자체는 Artifact 로 올리지 않습니다.** Artifact 는
  저장소 접근 권한만 있으면 누구나 받을 수 있고 보존 정책도 다릅니다.
  자료는 릴리스로만 갑니다.

## 안 될 때

### 로그인 실패

로그에 사이트가 보여준 메시지가 그대로 찍힙니다.

| 메시지 | 원인 |
|---|---|
| 비밀번호가 일치하지 않습니다 | Secrets 의 `ECLASS_PASSWORD` 를 갱신하세요 |
| 이미 로그인된 사용자입니다 | 다른 곳 세션을 로그아웃하거나 시간을 벌리세요 |
| 계정이 잠겼습니다 | **더 돌리지 마세요.** 학교에 문의해 푸세요 |
| 타임아웃 / 접속 불가 | 학교가 해외 IP 를 막았을 수 있습니다 |

마지막 경우에는 이 방식을 포기하고 로컬 작업 스케줄러를 쓰세요.

### 과목 목록이 비어 있음

로그인은 됐는데 과목을 못 찾은 것입니다. 학교가 페이지를 바꿨을
가능성이 큽니다. PC 에서 `scripts\eclass_probe.bat` 을 돌려 새 구조를
확인하세요.

### 릴리스 업로드 실패 (403)

워크플로의 `permissions: contents: write` 가 필요합니다.
저장소 Settings → Actions → General → Workflow permissions 가
**Read repository contents permission** 으로 묶여 있으면
**Read and write** 로 바꾸세요.

### 매번 전부 다시 받음

상태 캐시가 복원되지 않는 것입니다. 로그에서 `Cache restored` 를
찾아보세요. 7일 넘게 안 돌렸으면 캐시가 지워집니다 — 정상입니다.
업로드는 중복되지 않으니 그냥 두어도 됩니다.
